## 1. Scope Overview

WebCron은 24시간 상시 구동하며 크론 일정에 따라 작업을 실행하는 서버이다. 사용자는 웹 화면에서 작업을 관리하고, 실행 결과(성공·실패)와 감사 로그를 확인한다. 작업 유형은 두 가지이다.

- CLI 작업: node, python, sh, bat 등 OS 셸 명령을 실행한다. 종료 코드 0이면 성공이다.
- 웹훅 작업: GET 또는 POST 요청을 보낸다. 리다이렉트를 따라간 최종 응답이 2xx이면 성공이다.

## 2. Scope Boundaries

### In Scope

- 실행 중인 작업의 강제 중지
- 단일 계정 로그인, 평문 비밀번호의 enc 해시 자동 변환
- 작업 관리(생성·조회·수정·삭제, 활성 전환, 수동 실행)
- 크론 스케줄링(5/6필드, 설정 파일 타임존, 같은 작업의 병렬 실행, 타임아웃)
- CLI 작업과 웹훅 작업 실행
- 실행 이력과 감사 로그의 기록·조회·보관 기간 정리
- Windows와 Linux 지원

### Out of Scope

- 다중 사용자, 역할별 권한
- 실패 알림(메일, 메신저 등)
- 앱 자체의 HTTPS 처리(필요하면 리버스 프록시에서 처리)
- 서버가 꺼져 있던 동안 놓친 실행의 보충 실행
- 작업 간 의존 관계(선후행 실행)

## 3. Assumptions and Constraints

- 운영자는 1명이며, 서버에 접근할 수 있는 사람은 신뢰할 수 있다고 가정한다.
- CLI 작업은 서버 프로세스와 같은 OS 계정 권한으로 실행된다.
- 기본 바인딩 주소는 127.0.0.1이다. 외부에서 접속하려면 `.env` 의 `WEBCRON_HOST` 를 바꿔야 한다.
- 실행 이력도 감사 로그와 같은 `WEBCRON_LOG_RETENTION_DAYS` 보관 기간을 따른다.

### SEC-WEBCRON-002 — 평문 비밀번호를 enc 해시로 자동 변환

| Field | Value |
| --- | --- |
| Type | security |
| Target | v0.1 |
| Status | implemented |
| Priority | high |
| Tags | auth, password, config |
| Risk | high |
| Stability | evolving |
| Verification Method | test |
| GitHub Issue | - |
| Related Docs | - |

#### Requirement

시스템은 기동 시 설정 파일의 `WEBCRON_PASSWORD` 값이 `enc:` 접두사로 시작하지 않으면 평문으로 간주하고, 무작위 salt를 쓴 scrypt 해시를 `enc:` 형식으로 만들어 설정 파일의 그 줄을 작은따옴표로 감싼 값으로 교체해야 한다.

#### Rationale

사용자가 요구한 'enc' 저장 방식을 구현한다. 복호화 키가 같은 서버에 있으면 양방향 암호화는 보호 효과가 낮으므로 복호화할 수 없는 단방향 해시를 쓴다.

#### Acceptance Criteria

- [x] AC-1: 평문 비밀번호로 기동하면 설정 파일의 `WEBCRON_PASSWORD` 줄이 `WEBCRON_PASSWORD='enc:scrypt$...'` 형식으로 바뀌고, 파일 어디에도 평문 문자열이 남지 않는다.
- [x] AC-2: 변환 후 원래 평문 비밀번호로 로그인하면 성공한다.
- [x] AC-3: 값이 이미 `enc:` 형식이면 설정 파일을 수정하지 않는다.
- [x] AC-4: 파일은 임시 파일에 쓴 뒤 교체하는 방식으로 저장하며, 다른 줄(주석, 빈 줄, 다른 변수)은 그대로 유지된다.
- [x] AC-5: 변환하면 감사 로그에 `config.password_encrypted` 이벤트가 기록되며, 평문과 해시 값은 기록되지 않는다.

- [x] AC-6: 최종 URL, 상태 코드, 응답 본문(최대 64KB)이 실행 이력에 저장된다.
- [x] AC-7: 재시도 횟수가 N이면 실패 시 최대 N회 다시 시도하고, 실행 이력에 시도 횟수와 마지막 시도 결과를 기록한다.

#### Requirement

시스템은 사용자가 웹 화면에서 실행 중(running)인 실행 이력의 '중지'를 누르면 해당 실행을 즉시 중단하고 결과를 canceled로 기록해야 한다.

#### Rationale

타임아웃 기본값이 무제한이므로 멈춘 실행을 웹에서 끝낼 수단이 필요하다. 2026-10-13 사용자가 추가를 요청했다.

#### Acceptance Criteria

- [x] AC-1: CLI 실행을 중지하면 자식 프로세스까지 포함한 프로세스 트리 전체가 종료되고 결과가 canceled로 기록된다.
- [x] AC-2: 웹훅 실행을 중지하면 진행 중인 요청과 남은 재시도가 취소되고 결과가 canceled로 기록된다.
- [x] AC-3: 이미 끝난 실행에 중지를 요청하면 HTTP 409를 반환하고 결과를 바꾸지 않는다.
- [x] AC-4: 중지하면 감사 로그에 `run.cancel` 이벤트가 실행 ID와 작업 이름과 함께 기록된다.
- [x] AC-5: 통계와 목록에서 canceled 결과는 실패로 집계하지 않는다.
